1 📌 Introdução

Este relatório tem como objetivo registrar o aprendizado obtido ao longo das 26 aulas do Curso R Básico 2024, ministrado pelo Prof. Ben Dêivide de Oliveira Ferreira (DEFIM/CAP/UFSJ). O curso apresenta, de forma estruturada e progressiva, os fundamentos da linguagem R — desde a apresentação do ambiente de trabalho até conceitos avançados como criação de funções, pacotes e interface com outras linguagens.

O R é uma linguagem de programação voltada para computação estatística e visualização de dados, amplamente utilizada em pesquisa científica, análise de dados e engenharia. Este relatório sintetiza os principais tópicos abordados em cada aula, servindo como registro de estudo e consulta futura (Batista e Oliveira, 2022).

3 📚 Fundamentação Teórica

O R é uma linguagem e ambiente de programação desenvolvido por Ross Ihaka e Robert Gentleman na Universidade de Auckland, Nova Zelândia, na década de 1990, como uma implementação da linguagem S (Batista e Oliveira, 2022). Sua principal característica é ser open source e altamente extensível por meio de pacotes disponíveis no CRAN (Comprehensive R Archive Network).

A linguagem é estruturada em torno de três princípios centrais que permeiam todo o curso:

  • Princípio do Objeto: tudo em R é (ou pode ser tratado como) um objeto
  • Princípio da Função: toda ação em R é realizada por meio de funções
  • Princípio da Interface: o R se comunica com o sistema operacional, outras linguagens e fontes de dados externas

5.2 Aula 01 — Entendendo o Curso EAR: R Básico

Esta aula apresentou a base conceitual que orienta todo o curso. O ponto central foi a introdução dos três princípios fundamentais do R:

  • Princípio do Objeto: em R, tudo é um objeto — dados, resultados, funções e até ambientes são objetos manipuláveis
  • Princípio da Função: toda ação executada no R ocorre por meio de funções, sejam elas nativas ou criadas pelo usuário
  • Princípio da Interface: o R se comunica com o sistema operacional e pode importar e exportar dados de diversas fontes e formatos

Esses três princípios foram associados à visão geral do Ambiente R, fornecendo um mapa conceitual para o aprendizado ao longo do curso. A aula também incluiu orientações práticas sobre a instalação do R e do RStudio.

A aula complementou a caracterização do R e seu funcionamento interno, retomando e aprofundando os três princípios apresentados na Aula 01:

  • Princípio do Objeto: como os objetos são armazenados na memória RAM durante uma sessão R
  • Princípio da Função: como o R interpreta e executa funções a partir de comandos digitados no console
  • Princípio da Interface: como o R interage com o sistema operacional para leitura e escrita de arquivos

A aula encerrou com um exemplo ilustrativo que integrou os três princípios na prática, mostrando o fluxo completo de uma análise simples no R.

5.6 Aula 05 — Comandos no R e Ambiente Global

A aula abordou os fundamentos da interação do usuário com o R:

  • Console e Prompt de comando: o console é o canal de comunicação direta com o R; o prompt (>) indica que o R está pronto para receber um novo comando
  • Nomes sintáticos, não sintáticos e palavras reservadas: regras para nomear objetos no R — nomes válidos (sintáticos), nomes que exigem uso de crases (não sintáticos) e palavras reservadas que não podem ser usadas como nomes (if, else, TRUE, FALSE, etc.)
  • Comandos elementares:
    • Expressões: comandos que avaliam e retornam um resultado sem armazenar (ex.: 2 + 2)
    • Atribuições: comandos que armazenam o resultado em um objeto (ex.: x <- 10)
  • Chamada e correção de comandos com o RStudio: uso das teclas de atalho e do histórico de comandos para editar e reexecutar instruções
  • Ambiente Global: o Global Environment é um dos objetos mais importantes do R — o espaço de memória onde os objetos criados pelo usuário são armazenados durante a sessão

# Expressão: avalia e exibe, mas não armazena
2 + 2
[1] 4
Código 
# Atribuição: armazena o resultado no objeto x
x <- 10
x
[1] 10
Código 
# Verificando objetos no ambiente global
ls()
[1] "x"

5.7 Aula 06 — Arquivos .RData e .Rhistory

A aula apresentou dois arquivos gerados pelo R para persistência de dados entre sessões:

  • Finalidade do .RData: salva todos os objetos presentes no Ambiente Global ao encerrar uma sessão, permitindo restaurar o estado do trabalho ao reabrir o R
  • Finalidade do .Rhistory: registra o histórico de todos os comandos executados durante a sessão, funcionando como um log de atividades
  • Como criar esses arquivos: ao encerrar o R, ele pergunta se deseja salvar o workspace — ao confirmar, ambos os arquivos são gerados no diretório de trabalho. Também é possível criá-los manualmente com save.image() e savehistory()
  • Exemplos de aplicação: demonstração prática de salvar, fechar, reabrir o R e verificar que objetos e histórico foram preservados
Código 
# Salvando manualmente o ambiente
# save.image("meu_ambiente.RData")

# Carregando um ambiente salvo
# load("meu_ambiente.RData")

# Salvando o histórico manualmente
# savehistory("meu_historico.Rhistory")

5.8 Aula 07 — Criando e Salvando um Script

A aula introduziu o script como ferramenta fundamental para organizar e reproduzir análises:

  • O que é um Script? Um arquivo de texto com extensão .R que contém uma sequência de comandos R, permitindo que o código seja reutilizado, compartilhado e reproduzido
  • Como criar um Script:
    • Usando o R GUI: menu File → New Script
    • Usando o RStudio: menu File → New File → R Script (ou Ctrl + Shift + N)
  • Salvando um Script: Ctrl + S no RStudio; recomenda-se usar nomes descritivos e sem espaços (ex.: aula07_script.R)
  • Diretório de trabalho: pasta padrão onde o R lê e salva arquivos — verificado com getwd() e alterado com setwd()

5.9 Aula 08 — Objetos e Estrutura de Dados

Esta aula aprofundou o Princípio do Objeto e apresentou como o R organiza seus dados:

  • O que é um objeto? Qualquer entidade armazenada na memória do R — desde um simples número até uma função complexa
  • Tipos de objetos: o R possui tipos básicos (typeof) que definem a natureza dos dados: double, integer, complex, character, logical e raw
  • Atributos e metadados:
    • Atributos intrínsecos: typeof (tipo) e length (comprimento) — presentes em todo objeto
    • Classe (class): atributo que define como o objeto é tratado por funções genéricas
    • Demais atributos: dim, names, dimnames, entre outros
  • Estruturas de dados geradas pelos atributos: um vetor com atributo dim torna-se uma matriz; com class = "data.frame", torna-se um quadro de dados
  • Principais estruturas: vetor, matriz, array, lista e data frame
Código 
x <- c(1.5, 2.5, 3.5)
typeof(x)
[1] "double"
Código 
length(x)
[1] 3
Código 
attributes(x)
NULL

5.10 Aula 09 — Vetores

O vetor é a estrutura de dados mais fundamental do R:

  • Vetores atômicos: armazenam elementos de um único tipo (logical, integer, double, character, complex, raw)
  • Vetores escalares: vetores de comprimento 1 — em R, não existe tipo escalar separado; um único número é um vetor de comprimento 1
  • Vetores longos: vetores com múltiplos elementos, criados com c()
  • Manipulando vetores:
    • Indexação: acesso por posição (v[i]), por nome (v["nome"]) ou por condição lógica (v[v > 2])
    • Aritmética: operações aplicadas elemento a elemento (vetorização automática)
    • Outras operações: length(), rev(), sort(), which(), entre outras
Código 
v <- c(10, 20, 30, 40, 50)

# Indexação
v[3]
[1] 30
Código 
v[v > 25]
[1] 30 40 50
Código 
# Aritmética vetorizada
v * 2
[1]  20  40  60  80 100
Código 
v + c(1, 2, 3, 4, 5)
[1] 11 22 33 44 55

5.12 Aula 11 — Arrays (Matrizes Multidimensionais)

Os arrays generalizam o conceito de matriz para três ou mais dimensões:

  • Relação com vetores: um array é um vetor com atributo dim de comprimento 3 ou mais
  • Atributo dim para arrays: vetor de comprimento 3 composto por:
    • Número de linhas
    • Número de colunas
    • Número de matrizes (camadas)
Código 
# Array tridimensional: 3 linhas x 3 colunas x 2 matrizes

# Acessando a primeira camada

5.13 Aula 12 — Listas

As listas representam uma estrutura de dados mais complexa e flexível do que os vetores:

  • Objeto do tipo lista: criado com list(), é um tipo de objeto mais complexo do que um vetor
  • Heterogeneidade: pode conter simultaneamente vetores, funções, expressões e outros tipos
  • Objetos recursivos: listas podem conter outras listas dentro de si, formando estruturas hierárquicas
Código 
minha_lista <- list(
  nome     = "Yuri",
  notas    = c(8.5, 9.0, 7.8),
  aprovado = TRUE,
  info     = list(curso = "Engenharia", periodo = 10)
)

minha_lista$nome
[1] "Yuri"
Código 
minha_lista[["notas"]]
[1] 8.5 9.0 7.8
Código 
minha_lista[[4]]$curso
[1] "Engenharia"

O data frame é a estrutura tabular mais utilizada em análise de dados no R:

5.15 Aula 14 — Importando e Exportando Dados

A aula explorou o Princípio da Interface aplicado à comunicação com fontes de dados externas:

  • Princípio da Interface: o R é capaz de se comunicar com diferentes formatos de arquivo, tornando a importação e exportação parte central do fluxo analítico

5.16 Aula 15 — Funções

A aula aprofundou o Princípio da Função, apresentando as funções como objetos de primeira classe em R:

  • O que é uma função em R? Um objeto que recebe argumentos, executa operações e retorna um resultado
  • Tipos de funções:
    • Primitivas: implementadas em C, alta performance (ex.: sum(), length())
    • Closure: funções R puras, com corpo, argumentos e ambiente definidos
    • Especiais: operadores (+, <-) com comportamento diferenciado

  • Funções em pacotes: funções organizadas em pacotes que estendem as capacidades do R
  • Chamada de funções: passagem de argumentos por posição ou por nome

5.17 Aula 16 — Estruturas de Controle

As estruturas de controle direcionam o fluxo de execução de um programa:

  • Condicionais:
    • if() / else: executa um bloco se a condição for verdadeira; bloco alternativo se for falsa
    • ifelse(): versão vetorizada do if/else
  • Funções de loop:
    • for(): repete para cada elemento de um vetor ou lista
    • while(): repete enquanto uma condição for verdadeira
    • repeat: repete indefinidamente até encontrar um break
Código 
# if/else
x <- 15
if (x > 10) {
  cat("x é maior que 10\n")
} else {
  cat("x é menor ou igual a 10\n")
}
x é maior que 10
Código 
# ifelse vetorizado
valores <- c(3, 7, 12, 5, 18)
ifelse(valores > 10, "grande", "pequeno")
[1] "pequeno" "pequeno" "grande"  "pequeno" "grande"

# for

Iteração: 2 
Iteração: 3 
Iteração: 4
Código 
# while
k <- 1
while (k <= 3) {
  cat("Contagem:", k, "\n")
  k <- k + 1
}

Contagem: 2

5.18 Aula 17 — Como Criar Funções

A aula detalhou a criação de funções personalizadas no R:

  • Criação com function(): sintaxe básica para definir uma função
  • Estrutura de uma função:
    • Argumento: entradas da função; podem ter valores padrão
    • Corpo: bloco de instruções executadas
    • Ambiente: onde a função foi criada; define o escopo de busca de objetos
  • Formas de chamada:
    • Aninhada: funções chamadas dentro de outras
    • Intermediária: resultado armazenado em objeto antes de passar à próxima função
    • Pipe (|>): encadeamento legível de funções
  • Ordenamento de argumentos: R permite passagem por posição ou por nome
  • Objeto ...: permite número variável de argumentos, repassados a outras funções
  • Escopo léxico: o R busca objetos primeiro no ambiente próprio da função, depois no ambiente envolvente
    • Ambiente envolvente: onde a função foi criada
    • Ambiente de execução: criado a cada chamada e destruído ao término
  • Novo começo: a cada chamada, a função começa do zero, sem memória de execuções anteriores
Código 
# Função com argumento padrão
saudacao <- function(nome, prefixo = "Olá") {
  cat(prefixo, nome, "!\n")
}
saudacao("Yuri")
Olá Yuri !
Código 
saudacao("Prof. Ben", prefixo = "Bom dia,")
Bom dia, Prof. Ben !
Código 
# Uso do objeto ...
minha_soma <- function(...) sum(c(...))
minha_soma(1, 2, 3, 4, 5)
[1] 15
Código 
# Escopo léxico
y <- 100
f <- function() cat("y do ambiente envolvente:", y, "\n")
f()
y do ambiente envolvente: 100

5.19 Aula 18 — Boas Práticas de Como Escrever um Código

A aula destacou a importância de escrever código legível, organizado e compartilhável:

  • Motivação: código bem escrito é mais fácil de entender, manter, depurar e compartilhar
  • Ferramentas do RStudio: formatação automática, destaque de sintaxe e diagnóstico de código
  • Nomes de arquivos: descritivos, sem espaços, com convenção consistente (ex.: 01_importacao_dados.R)
  • Comentários: documentar o porquê das decisões, não apenas o o quê o código faz
  • Nomes de objetos: preferir nomes descritivos em snake_case (ex.: media_notas, não mn)
  • Sintaxe: espaços ao redor de operadores e após vírgulas; linhas com no máximo 80 caracteres
  • Hierarquia e alinhamento: seguir a indentação de acordo com a estrutura do código

  # Calcula (x + y)^2 pela identidade algébrica

5.20 Aula 19 — Pacotes

A aula apresentou o ecossistema de pacotes como principal mecanismo de extensão do R:

  • Motivação: funções nativas têm escopo limitado; pacotes permitem adicionar novas funcionalidades
  • Informações básicas: um pacote é uma coleção organizada de funções, dados e documentação
  • Esqueleto de um pacote: diretórios R/, man/, arquivos DESCRIPTION e NAMESPACE
  • Instalação:
    • CRAN: install.packages("nome") — repositório oficial, pacotes revisados
    • GitHub: remotes::install_github("usuario/repositorio") — versões em desenvolvimento
    • Arquivo local: install.packages("pacote.tar.gz", repos = NULL, type = "source")
  • Pacotes desativados: pacotes removidos do CRAN por inatividade ou problemas de manutenção
  • Objetivo de um pacote: encapsular e distribuir funcionalidades de forma padronizada
  • Funções em um pacote: funções exportadas (disponíveis ao usuário) e funções internas (uso privado)

5.21 Aula 20 — Carregando e Anexando Pacotes

A aula distinguiu dois conceitos frequentemente confundidos:

  • Motivação: entender a diferença entre carregar e anexar é essencial para evitar conflitos de nomes e compreender o comportamento do R
  • Como instalar um pacote: install.packages() — executado uma única vez
  • Como anexar um pacote: library() — executado no início de cada sessão; adiciona o pacote ao caminho de busca
  • Implicações:
    • Carregar (loadNamespace()): torna o pacote disponível em memória, mas funções só acessíveis via :: — sem alterar o caminho de busca
    • Anexar (library()): carrega e insere o pacote no caminho de busca, tornando suas funções diretamente acessíveis

5.22 Aula 21 — NAMESPACE de um Pacote

O NAMESPACE é o mecanismo que controla a visibilidade das funções de um pacote:

  • O que é o NAMESPACE? Arquivo que define quais funções são exportadas (visíveis ao usuário) e quais são importadas de outros pacotes
  • Funções exportadas vs. internas: exportadas ficam disponíveis ao anexar o pacote; internas são de uso privado e acessíveis apenas via :::
  • Prevenção de conflitos: o NAMESPACE impede que funções de pacotes diferentes com o mesmo nome se sobrescrevam, garantindo isolamento entre dependências
  • Importância no desenvolvimento: ao criar um pacote, o NAMESPACE define claramente sua interface pública e suas dependências externas

5.23 Aula 22 — Quando Utilizar os Operadores :: e :::

A aula apresentou os operadores de acesso a namespaces e suas aplicações práticas:

  • Operador ::: acessa funções exportadas de um pacote sem anexá-lo com library(). Útil para evitar ambiguidade quando dois pacotes possuem funções com o mesmo nome
  • Operador :::: acessa funções internas (não exportadas) de um pacote. Deve ser usado com cautela, pois essas funções não fazem parte da interface pública e podem mudar sem aviso
  • Quando preferir :: a library(): em scripts que usam poucas funções de um pacote, para deixar explícita a origem e evitar poluir o caminho de busca
Código 
# Usando :: para explicitar a origem da função
resultado <- base::mean(c(1, 2, 3, NA), na.rm = TRUE)

5.24 Aula 23 — Ambientes e Caminho de Busca

A aula aprofundou a estrutura interna de ambientes do R:

  • Hierarquia de ambientes: o R organiza os ambientes em cadeia hierárquica — cada ambiente possui um ambiente pai; o topo é o ambiente vazio (emptyenv())
  • Caminho de busca (search path): sequência de ambientes percorrida pelo R ao procurar um objeto ou função — inicia no Global Environment e percorre os pacotes anexados até o pacote base
  • Função search(): exibe o caminho de busca atual
  • Efeito de library(): ao anexar um pacote, ele é inserido logo após o Ambiente Global no caminho de busca
  • Ambientes locais em funções: cada chamada de função cria um ambiente de execução temporário, descartado ao término

## 📚 Fundamentação Teórica

O R é uma linguagem e ambiente de programação desenvolvido por Ross Ihaka e Robert Gentleman na Universidade de Auckland, Nova Zelândia, na década de 1990, como uma implementação da linguagem S [@Rbasico2022]. Sua principal característica é ser *open source* e altamente extensível por meio de pacotes disponíveis no CRAN (*Comprehensive R Archive Network*).

A linguagem é estruturada em torno de três princípios centrais que permeiam todo o curso:

- **Princípio do Objeto:** tudo em R é (ou pode ser tratado como) um objeto
- **Princípio da Função:** toda ação em R é realizada por meio de funções
- **Princípio da Interface:** o R se comunica com o sistema operacional, outras linguagens e fontes de dados externas

### Aula 08 — Objetos e Estrutura de Dados

### Aula 09 — Vetores

O vetor é a estrutura de dados mais fundamental do R:

- **Vetores atômicos:** armazenam elementos de um único tipo (`logical`, `integer`, `double`, `character`, `complex`, `raw`)
- **Vetores escalares:** vetores de comprimento 1 — em R, não existe tipo escalar separado; um único número é um vetor de comprimento 1
- **Vetores longos:** vetores com múltiplos elementos, criados com `c()`
- **Manipulando vetores:**
  - *Indexação:* acesso por posição (`v[i]`), por nome (`v["nome"]`) ou por condição lógica (`v[v > 2]`)
  - *Aritmética:* operações aplicadas elemento a elemento (vetorização automática)
  - *Outras operações:* `length()`, `rev()`, `sort()`, `which()`, entre outras

```{r}
v <- c(10, 20, 30, 40, 50)

# Indexação
v[3]
v[v > 25]

# Aritmética vetorizada
v * 2
v + c(1, 2, 3, 4, 5)
```

### Aula 11 — Arrays (Matrizes Multidimensionais)

Os arrays generalizam o conceito de matriz para três ou mais dimensões:

- **Atributo `dim` para arrays:** vetor de comprimento 3 composto por:
  - Número de linhas
  - Número de colunas
  - Número de matrizes (camadas)

### Aula 14 — Importando e Exportando Dados

A aula explorou o Princípio da Interface aplicado à comunicação com fontes de dados externas:

- **Princípio da Interface:** o R é capaz de se comunicar com diferentes formatos de arquivo, tornando a importação e exportação parte central do fluxo analítico
- **Como organizar um banco de dados:** uma observação por linha, uma variável por coluna, sem células mescladas
- **Como importar dados para o R:**

### Aula 15 — Funções

A aula aprofundou o Princípio da Função, apresentando as funções como objetos de primeira classe em R:

- **O que é uma função em R?** Um objeto que recebe argumentos, executa operações e retorna um resultado
- **Tipos de funções:**
  - *Primitivas:* implementadas em C, alta performance (ex.: `sum()`, `length()`)

- **Chamada de funções:** passagem de argumentos por posição ou por nome

### Aula 16 — Estruturas de Controle

As estruturas de controle direcionam o fluxo de execução de um programa:

- **Condicionais:**
  - `if()` / `else`: executa um bloco se a condição for verdadeira; bloco alternativo se for falsa
  - `ifelse()`: versão vetorizada do `if/else`
- **Funções de loop:**
  - `for()`: repete para cada elemento de um vetor ou lista
  - `while()`: repete enquanto uma condição for verdadeira
  - `repeat`: repete indefinidamente até encontrar um `break`

```{r}
# if/else
x <- 15
if (x > 10) {
  cat("x é maior que 10\n")
} else {
  cat("x é menor ou igual a 10\n")
}

# ifelse vetorizado
valores <- c(3, 7, 12, 5, 18)
ifelse(valores > 10, "grande", "pequeno")

# for
for (i in 1:4) cat("Iteração:", i, "\n")

# while
k <- 1
while (k <= 3) {
  cat("Contagem:", k, "\n")
  k <- k + 1
}
```

### Aula 17 — Como Criar Funções

A aula detalhou a criação de funções personalizadas no R:

- **Criação com `function()`:** sintaxe básica para definir uma função
- **Estrutura de uma função:**
  - *Argumento:* entradas da função; podem ter valores padrão
  - *Corpo:* bloco de instruções executadas
  - *Ambiente:* onde a função foi criada; define o escopo de busca de objetos
- **Formas de chamada:**
  - *Aninhada:* funções chamadas dentro de outras
  - *Intermediária:* resultado armazenado em objeto antes de passar à próxima função
  - *Pipe (`|>`):* encadeamento legível de funções
- **Ordenamento de argumentos:** R permite passagem por posição ou por nome
- **Objeto `...`:** permite número variável de argumentos, repassados a outras funções
- **Escopo léxico:** o R busca objetos primeiro no ambiente próprio da função, depois no ambiente envolvente
  - *Ambiente envolvente:* onde a função foi criada
  - *Ambiente de execução:* criado a cada chamada e destruído ao término
- **Novo começo:** a cada chamada, a função começa do zero, sem memória de execuções anteriores

```{r}
# Função com argumento padrão
saudacao <- function(nome, prefixo = "Olá") {
  cat(prefixo, nome, "!\n")
}
saudacao("Yuri")
saudacao("Prof. Ben", prefixo = "Bom dia,")

# Uso do objeto ...
minha_soma <- function(...) sum(c(...))
minha_soma(1, 2, 3, 4, 5)

# Escopo léxico
y <- 100
f <- function() cat("y do ambiente envolvente:", y, "\n")
f()
```

### Aula 18 — Boas Práticas de Como Escrever um Código

A aula destacou a importância de escrever código legível, organizado e compartilhável:

- **Motivação:** código bem escrito é mais fácil de entender, manter, depurar e compartilhar
- **Ferramentas do RStudio:** formatação automática, destaque de sintaxe e diagnóstico de código
- **Nomes de arquivos:** descritivos, sem espaços, com convenção consistente (ex.: `01_importacao_dados.R`)
- **Comentários:** documentar o *porquê* das decisões, não apenas o *o quê* o código faz
- **Nomes de objetos:** preferir nomes descritivos em *snake_case* (ex.: `media_notas`, não `mn`)
- **Sintaxe:** espaços ao redor de operadores e após vírgulas; linhas com no máximo 80 caracteres

### Aula 19 — Pacotes

A aula apresentou o ecossistema de pacotes como principal mecanismo de extensão do R:

- **Motivação:** funções nativas têm escopo limitado; pacotes permitem adicionar novas funcionalidades
- **Informações básicas:** um pacote é uma coleção organizada de funções, dados e documentação
- **Esqueleto de um pacote:** diretórios `R/`, `man/`, arquivos `DESCRIPTION` e `NAMESPACE`
- **Instalação:**
  - *CRAN:* `install.packages("nome")` — repositório oficial, pacotes revisados
  - *GitHub:* `remotes::install_github("usuario/repositorio")` — versões em desenvolvimento
  - *Arquivo local:* `install.packages("pacote.tar.gz", repos = NULL, type = "source")`
- **Pacotes desativados:** pacotes removidos do CRAN por inatividade ou problemas de manutenção
- **Objetivo de um pacote:** encapsular e distribuir funcionalidades de forma padronizada
- **Funções em um pacote:** funções exportadas (disponíveis ao usuário) e funções internas (uso privado)

### Aula 20 — Carregando e Anexando Pacotes

A aula distinguiu dois conceitos frequentemente confundidos:

- **Motivação:** entender a diferença entre carregar e anexar é essencial para evitar conflitos de nomes e compreender o comportamento do R
- **Como instalar um pacote:** `install.packages()` — executado uma única vez
- **Como anexar um pacote:** `library()` — executado no início de cada sessão; adiciona o pacote ao caminho de busca
- **Implicações:**
  - *Carregar* (`loadNamespace()`): torna o pacote disponível em memória, mas funções só acessíveis via `::` — sem alterar o caminho de busca
  - *Anexar* (`library()`): carrega e insere o pacote no caminho de busca, tornando suas funções diretamente acessíveis

```{r}
# Caminho de busca antes e depois de anexar
search()
library(stats)
search()
```

### Aula 21 — NAMESPACE de um Pacote

O NAMESPACE é o mecanismo que controla a visibilidade das funções de um pacote:

- **O que é o NAMESPACE?** Arquivo que define quais funções são *exportadas* (visíveis ao usuário) e quais são *importadas* de outros pacotes
- **Funções exportadas vs. internas:** exportadas ficam disponíveis ao anexar o pacote; internas são de uso privado e acessíveis apenas via `:::`
- **Prevenção de conflitos:** o NAMESPACE impede que funções de pacotes diferentes com o mesmo nome se sobrescrevam, garantindo isolamento entre dependências
- **Importância no desenvolvimento:** ao criar um pacote, o NAMESPACE define claramente sua interface pública e suas dependências externas

### Aula 22 — Quando Utilizar os Operadores `::` e `:::`

A aula apresentou os operadores de acesso a namespaces e suas aplicações práticas:

- **Operador `::`:** acessa funções *exportadas* de um pacote sem anexá-lo com `library()`. Útil para evitar ambiguidade quando dois pacotes possuem funções com o mesmo nome
- **Operador `:::`:** acessa funções *internas* (não exportadas) de um pacote. Deve ser usado com cautela, pois essas funções não fazem parte da interface pública e podem mudar sem aviso
- **Quando preferir `::` a `library()`:** em scripts que usam poucas funções de um pacote, para deixar explícita a origem e evitar poluir o caminho de busca

```{r}
# Usando :: para explicitar a origem da função
resultado <- base::mean(c(1, 2, 3, NA), na.rm = TRUE)
resultado

x <- stats::rnorm(10, mean = 0, sd = 1)
round(x, 2)
```

### Aula 23 — Ambientes e Caminho de Busca

A aula aprofundou a estrutura interna de ambientes do R:

- **Hierarquia de ambientes:** o R organiza os ambientes em cadeia hierárquica — cada ambiente possui um *ambiente pai*; o topo é o ambiente vazio (`emptyenv()`)
- **Caminho de busca (*search path*):** sequência de ambientes percorrida pelo R ao procurar um objeto ou função — inicia no Global Environment e percorre os pacotes anexados até o pacote `base`
- **Função `search()`:** exibe o caminho de busca atual
- **Efeito de `library()`:** ao anexar um pacote, ele é inserido logo após o Ambiente Global no caminho de busca
- **Ambientes locais em funções:** cada chamada de função cria um ambiente de execução temporário, descartado ao término

```{r}
search()

environmentName(globalenv())
environmentName(baseenv())

# Criando e usando um ambiente manualmente
meu_amb <- new.env()
assign("x", 42, envir = meu_amb)
get("x", envir = meu_amb)
```
